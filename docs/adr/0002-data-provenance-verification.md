# ADR-0002: 数据真实性门槛——模型记忆不作为事实来源

日期：2026-09-07 · 状态：已接受

## 背景

混用多模型执行时出现严重幻觉事故：reports 001-010 由某次会话生成，挂牌 URL 为占位符（`107100000001.html` 重定向回首页），"已核验"数据无任何来源。实采核验（浏览器通道）发现（以下案例均已去标识）：

- **001（某小区）**：小区在平台城市库不存在（宽搜仅命中外地近似名楼盘）→ 整份报告作废；
- **008（某小区）**：小区真实，但报告核心挂牌（121㎡/560 万/46,281 元/㎡）不存在——实采在售为 100-102㎡ 三居 530-570 万（52-57k 元/㎡），小区均价 54,031；容积率、物业费、绿化率均与实采不符；
- **002/005/009（某三小区）**：价格或板块与平台实况明显不符（A 小区实采均价 64,142 vs 报告 46,000；B 小区实址与报告板块相差一个行政区；C 小区实址在邻板块而非报告所写）；
- 另有 Fit 表按虚构画像口径打分（"通勤约束 Low：全域放开"，与用户真实锚点矛盾）。

## 决策

1. **合法事实来源只有三类**：政府背书（高概率可信，仍标 as_of）、本会话实采（URL 可复核）、用户提供的原始材料。**模型记忆与历史会话的"已核验"结论不构成来源**——引用前必须本会话重新验证。
2. **交叉验证门槛**：关键字段（存在性/价格/面积/学区对口/配套距离）≥2 独立来源或 1 个政府背书来源；不满足 → 待核实清单，不得作为评分依据。
3. **作废而非降权**：房源实体无法证实存在 → 整份报告作废；板块数据无来源 → 该板块数据作废。
4. **采集留痕**：scan 记录增加 `capture` 字段（channel/captured_at/url_verified）；`detect` 输出的 URL 必须实际访问验证。

## 后果（2026-09-09 补充强约束条款）

- **provenance 过滤是强约束，下沉在共享数据层强制执行**：`collectReports` / `parseWatchlist` 默认排除 void，任何新增的数据消费入口（脚本、页面、导出）自动继承该行为——不要在消费端重复实现过滤，也不要 opt-in 除非是明确的审计需求。
- **长期跟踪确认可信度**：单次快照的可信度有上限。同一房源的多次扫描自动聚合为价格历史（`scan.mjs history`），每次复扫的实采证据跑 `verify` 判定表——provenance 随证据**可升级（suspect → verified）也可降级**（verified → suspect，如复扫发现挂牌虚构/价格异常）。对接政务公开数据源（见 `templates/official-sources.cn.yml`）是最高优先信源。
- **目标是省用户时间**：强约束的意义在于用户不需要反复人工核对——系统用机器判定 + 政府背书 + 时间序列，把"这条数据可不可信"变成脚本的输出而不是用户的负担。

## 后果

- 评估/扫描执行成本上升（多 1-2 次验证抓取）——用预算内抓取换整份报告可信度，值得。
- 规则落在 `AGENTS.md`（反幻觉纪律节）、`modes/_shared.md`（来源真实性与反幻觉节 + NEVER 11 / ALWAYS 11）、`modes/evaluate.md`（Gate — 来源真实性）、`modes/scan.md`（capture 字段）。
- 历史报告 001-010 逐套标注"待实采核验"，未验证前不得作为决策依据。
- 未来不要提议放宽此门槛（例如"信 AI 记忆以省 token"）；若抓取环境受限导致无法实采，正确行为是把数据标「未核实」并明示，而不是采信记忆。
