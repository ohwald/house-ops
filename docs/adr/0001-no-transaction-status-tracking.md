# ADR-0001: 不做房源交易状态跟踪（无状态机、无进度漏斗）

日期：2026-09-05 · 状态：已接受

## 决策

house-ops **不跟踪房源的交易状态**。移除整个状态机子系统：`templates/states.yml`（canonical 状态与别名）、watchlist 的"状态"列、dashboard 的进度漏斗与状态选择器、doctor 的状态校验、stats 的流转漏斗分析。

watchlist 退化为**纯候选清单**：编号 / 小区 / 板块 / 类型 / 总价 / 评分 / 风险 / 日期 / 备注。"看过没看过""弃了没弃"这类事实直接写进备注（如"弃购：噪音硬伤"），不设枚举约束。

## 理由（load-bearing）

1. **一次性购房不需要 CRM**：本工具的使命到"签约前核实"为止（contract 模式收尾）；网签/过户是现实世界的事，追踪它对决策零贡献。
2. **维护成本已被实证**：状态机是本仓库第一个活体 bug 的来源（states.yml 与 doctor 硬编码副本枚举漂移，导致合法状态被误判非法）。一个没有活跃消费者的枚举子系统，其 SoT 同步成本（mode 文件、脚本、校验、文档四处）超过收益。
3. **分析价值已有更优载体**：弃购/失分分析的数据源是评估报告 Machine Summary 的 `conclusion`（pass/conditional/...）与 watchlist 备注，状态列从来只是冗余。

## 后果

- watchlist 表结构变更：删除"状态"列；历史数据迁移时把状态值折进备注。
- doctor 不再校验状态合法性（保留编号↔报告对应检查）。
- dashboard 的 `s`（状态变更）/`a`（过滤弃购）快捷键与漏斗看板移除。
- 未来架构评审**不要**重新提议状态机、进度漏斗或交易阶段跟踪；若用户工作流变化需要它，应作为新决策 reopen 本 ADR，而不是悄悄加回。
