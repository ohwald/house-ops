# Mode: triage — 阶段一：房源初筛与范围圈定

触发：`/house-ops triage` + 房源链接/描述，或用户说"快速筛一下""值不值得点开看"。目标：**作为决策两阶段工作流的第一步，60 秒内圈定范围、排除硬伤**，只花完整评估 1/5 的 token。筛选通过后方可进入【第二阶段：多源交叉验证与深度分析】（`evaluate`）。

前置阅读：`modes/_brief.md`（存在才读；不存在时提示"先跑 intake 或手填 _brief.md，速筛会退化成凭空猜"，并允许用户口头给硬门槛继续）。

## 流程

1. **解析输入**：链接→WebFetch 一次；文字→直接用。缺口信息**不联网补全**（这是与 evaluate 的关键区别），缺失项直接算"未知"。
2. **速筛三问**（对照 `_brief.md` 硬门槛）：
   - 预算内吗？（对照 walk-away；未知记"待确认"）
   - 位置/板块在可接受范围吗？
   - 触发一票否决吗？（无电梯+行动不便老人、商办产权、动迁混居红线等）
3. **理想要点粗对**：对 `_brief.md` 理想要点逐条 `✅/⚠️/⛔/未知`，一行一条。
4. **输出阶段一速筛卡**（对话内直接输出，不落报告文件）：

```
阶段一初筛：{小区名}  {总价}万 {面积}㎡ {户型}
预算   ✅ 480万 ∈ [420, 500]
位置   ✅ 浦东金桥辐射圈
红线   ⛔ 无硬性DQ触发
理想   学区 ⚠️待核实 | 地铁 ✅800m | 三居 ✅ | 房龄 ✅15年内
结论：✅ 初筛通过，建议进入【阶段二：多源交叉验证与深度分析】(/house-ops evaluate) / ⛔ 排除：触碰硬性红线
```

## 边界

- 速筛结论**不写入 watchlist、不生成报告、不更新编号**。
- 速筛通过 ≠ 评分 ≥4.0；只代表"值得花一次完整评估的 token"。
- 同一房源第二次速筛（用户补充了信息）：直接对照新信息修正结论，不重复已确认项。
- 完整评估时速筛结果可复用（用户贴链接时提示"已有速筛结论，将基于此评估"）。
