# Mode: stats — 找房数据统计与模式分析

触发：`/house-ops stats` 或"统计一下/我的找房数据"。数据源：`reports/*.md` 的 Machine Summary（schema SoT = evaluate.md；`scripts/stats.mjs` 是同一契约的无 AI 实现，优先跑脚本再人工补充解读）。

## 输出

1. **总览**：已评估 N 套；各结论分布（strong_buy / worth_viewing / conditional / pass）；分数分布直方图（0.5 一档）。
2. **板块/城市分布**：哪几个板块看得多？哪个板块平均分最高？
3. **价格带**：已评估房源的价格带 vs 画像预算区间——评估是集中在预算上沿还是全区间？预算是否定得不现实（普遍超上限才命中好货）？
4. **失分模式**：汇总各报告低分维度（<3 的维度计数排行）——如果"价格合理性"普遍低，说明预算与市场错位；如果"需求匹配"普遍低，说明画像要求超出预算，提示回到 intake 重新取舍。
5. **流转漏斗**：watchlist 各状态数量与平均停留天数（关注→已评估→已看房→谈判中），卡壳环节点名。
6. **弃购原因排行**：从 watchlist 备注与报告结论中归纳前 3 个弃购原因。
7. **建议**：基于以上给 2-3 条可执行建议（调画像 / 调预算 / 集中看某板块 / 加快谈判节奏）。

用户同意时把摘要落盘 `data/stats-{YYYY-MM-DD}.md`。

## 边界

- 样本 < 5 套时明说"样本太少，模式分析仅供参考"。
- 只统计、不联网；全程不修改报告与 watchlist。
