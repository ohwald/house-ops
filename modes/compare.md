# Mode: compare — 多盘横向对比

触发：`/house-ops compare 001 003 005`（编号）或"把这几套对比一下"。对象：**2-6 套已有评估报告的房源**（无报告的先跑 evaluate；混入未评估房源时先提示）。

前置阅读：`_shared.md`、`_profile.md`、待对比各套的 `reports/` 报告。

## 流程

1. **加载报告**：按编号读取各套 Machine Summary + 五维分数 + 关键事实；缺报告的房源列出并停止。
2. **对比矩阵**（对话输出；用户要求时可落 `reports/compare-{YYYY-MM-DD}.md`）：

| 维度 | 001 ××小区 | 003 ××小区 | 005 ××小区 |
|---|---|---|---|
| 挂牌价 / 单价 | | | |
| **政策与交易成本**（契税/增值税/个税精算、到手全口径现金成本、首套/二套信贷空间） | | | |
| **历史成交与抗跌性**（历史周期回调、真实折价空间、年均去化与流动性） | | | |
| **地段现状与城市规划**（现状配套、规划地铁推进确定性、周边未建地块用途与遮挡变数） | | | |
| Fit（对照画像核心项：预算/户型/通勤/学区/电梯适老幼儿等） | | | |
| Property（房龄次新、户型结构、物业软素质代理信号） | | | |
| Risk（政策锁定制、产权、开发商/交付、最重风险项） | | | |
| **综合评级** | | | |

3. **逐维点评**：每维 1-2 句"谁胜出、为什么、代价差多少"，引用各报告的可靠度档位；可靠度不同的数据（如 001 是成交数据、003 只有挂牌数据）必须提示不可直接比。
4. **多方案场景化推演（多路径中立对照，不设单一绝对胜出者）**：
   - **方案 A（极致自住品质与舒适流）**：推荐 X，但指出其首付与溢价成本；
   - **方案 B（稳健抗跌与高性价比流）**：推荐 Y，历史折价空间充足、流动性好，但牺牲了某些次要偏好；
   - **方案 C（规划红利与长持成长流）**：推荐 Z，博取规划轨交与新校兑现，但需承受施工期与不确定性；
   - 明确各方案的收益与代价，让用户根据家庭当前风险偏好自主权衡。
5. **组合视角**：如果各套预算/板块接近，提示"这是二选一格局，建议对前二名跑 deep-dive 后再决定"；如果分布在不同板块，提示"可都进入看房清单，按看房动线排序"。
6. **同步**：对话内询问是否更新 watchlist 备注列（如"对比后优先级 ↑/↓"）。

## 边界

- 不重新联网调研（深挖属于 deep-dive）；只用既有报告 + 必要时读报告内引用。
- 各套评估日期差 > 60 天时，提示旧报告的价格结论可能过时，建议先增量重评。
- 综合评分 相差 < 0.3 视为"分不出"，明确说"这两套本质上打平，决定因素变成看房现场感受与谈判结果"，并建议都约看。
