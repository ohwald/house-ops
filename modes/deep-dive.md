# Mode: deep-dive — 高分房源六轴深挖

触发：`/house-ops deep-dive [编号|小区名|URL]`。**前置条件：该房源 Global ≥ 4.0**（低于门槛时说明原因并停止；用户在 `_custom.md` 显式降门槛的除外）。

前置阅读：`_shared.md`、`_profile.md`、对应评估报告（`reports/` 中查找；不存在则先跑 evaluate）。

## 研究预算

WebSearch/WebFetch 合计 ≤ 12 次，超出时列出未查项请用户决定。所有事实带来源与 `as_of` 日期；查不到的写"未核实"，不推断。

## Step 0 — 定位对象

按编号/小区名在 watchlist 与 reports/ 中定位房源与既有报告；两者都没有时请用户提供链接先评估。

## 六轴调研

### 轴 1 — 价格历史

- 小区近 12-24 个月成交价走势（挂牌量、成交量、涨跌幅度）
- 本套挂牌期间的调价记录与在售时长
- 板块整体走势与政策影响（如利率、限购放松的时间点）
- 输出：当前价位处于近两年区间的什么位置（高位/中位/低位）+ 依据

### 轴 2 — 周边环境

- 嫌恶设施复核（高压线/垃圾站/殡葬/工厂/高架）——evaluate 阶段"未核实"的逐项闭环
- 噪音与气味源：主干道、铁路、航线、餐饮街
- 负面规划：已批复的拆迁/新建/改道（规划文件优于自媒体传言）
- 输出：环境风险清单（无 / 有-可接受 / 有-减分）

### 轴 3 — 本地政策

读 `templates/policy-notes.cn.yml` 起步，逐项联网核实 `as_of`：

- 限购：用户资格在该城市该房源类型下是否可购
- 贷款：当前首付比例区间与利率区间（首套/二套），对照画像付款方式估算月供区间
- 税费：契税/增值税/个税的最新口径，结合本套年限与房东套数假设估算总税费
- 学区（若画像权重 ≥ 中）：对口划片的官方口径、学位占用规则、多校划片风险
- 输出：政策要点表（每行：项目/当前口径/对这套房的影响/as_of）

### 轴 4 — 竞品与供给

- 同小区在售同户型对比（价格、楼层、装修差异）→ 是否有更优替代在售
- 同价位 2-3 个替代盘的简要对比（适合度粗评，不展开完整评估）
- 小区去化速度 → 判断"不用急"还是"好房会被抢"
- 输出：竞品表 + 紧迫度结论（可慢慢挑 / 时机窗口 / 建议尽快约看）

### 轴 5 — 交易安全

输出一份**核验清单**（用户去核实，AI 无法远程核实的如实说明）：

- 不动产权证：产权人、共有人、抵押/查封状态（可要求房东提供拉产调）
- 户口与学位占用情况及迁出约定
- 租约占用（买卖不破租赁）
- 物业费/水电燃气/供暖欠费
- 新房另加：五证、网签备案流程、资金监管账户

### 轴 6 — 生活圈

- 通勤实测估算：画像通勤锚点 → 地铁/驾车用时区间（工作日早高峰口径），标注是估算非实测
- 日常配套步行圈：菜场/超市、幼儿园/学校、医院、公园（各标距离）
- 对照 `_profile.md` 生活方式（如老人同住、宠物、在家办公）给适配性短评

## 输出

写 `reports/{同编号}-{小区slug}-{YYYY-MM-DD}-deep.md`：

1. 头部：房源、原 Global 评分、深挖日期、`as_of` 汇总
2. 六轴各一节，每节以**"对决策的影响"**一句话收尾（不堆信息）
3. `## 深挖结论`：维持原评分 / 上调 / 下调（说明理由与是否触发封顶）+ 置信度变化
4. `## 待用户核实清单`：交易安全轴与所有"未核实"项的合并清单，按优先级排序
5. `## 下一步`：建议运行 negotiate / 约看 / 放弃

Post：更新 watchlist（状态按用户进度，评分若有变则同步），回复用户报告路径 + 一段话结论。
