# Mode: evaluate — 阶段二：多源交叉验证与深度客观分析

输入：房源 URL 或文字描述（来自阶段一初筛入围或用户直接指定）。输出：`reports/{NNN}-{小区slug}-{YYYY-MM-DD}.md` 深度评级报告 + watchlist 登记。
前置阅读：`_shared.md`（评分体系、去伪存真对照表、配套分级）、`_profile.md`、`_custom.md`。

**核心准则**：本阶段的核心任务是**剥离营销噪音、通过多源交叉验证提炼客观事实，输出中立的多方案权衡推演**。绝不采信中介与开发商的口头宣传。

## Step 0 — 输入解析与多源信息获取

- URL：WebFetch 抓取挂牌页；失败时尝试一次搜索快照/其他平台同源挂牌。
- `data/scans/` 已有该房源扫描记录（scan 模式产物）时直接引用其"挂牌 vs 成交"交叉验证；政务公开源补充。
- 纯文字描述：直接采用，标"用户提供"。
- 联网多源交叉验证：搜索住建局官方备案、发改委批复工期、教育局学区公示、规划局控规。

**Gate — 信息充分性**：以下 5 项至少齐 4 项才进入评分：城市+区/板块、总价或单价、面积、户型、楼层/房龄任一。不足时列出缺口请用户补充。

**Gate — 来源真实性（反幻觉，先于一切评分）**：① 房源 URL 必须实际访问——重定向到首页/搜索页 = 占位符；② 小区必须在链家/贝壳小区库可检索到。两者任一失败且用户无法提供真实来源 → **报告作废**（不是降权），watchlist 标注「报告作废」。**机械判定跑 `node scripts/scan.mjs verify <record.json> --evidence <实采证据.json>`**（判定表见 modes/scan.md；provenance_suggestion 写入 Machine Summary）。定稿时把核验结果写进 Machine Summary 的 `provenance` 字段（统计/清单按此过滤：void 不参与统计与默认展示）。报告内每个关键事实带来源标记：`[实采]`（本会话抓取，URL 可复核）/ `[政务]`（政府背书，带 as_of）/ `[用户提供]` / `[未核实]`——无标记的关键数据不得出现在评分依据里；「已核验」类表述若本会话未实际验证，一律改为「未核实」。

## Step 1 — 房源类型检测与营销噪音过滤

判定并写入报告：`二手住宅 | 新房(期房/现房) | 法拍房 | 商办公寓(40/50年) | 别墅 | 保障房/共有产权 | 回迁安置 | 其他`。

## Block A — 房源基本盘与关键客观核验事实

> **内部评估纪律（Internal Discipline，无需向用户外显说明）**：
> AI 在评估全程中必须在内心严格剥离营销噪音——绝不将中介口述、宣传海报或开发商宣传词作为加分依据。在内部自动通过政务源、法定控规与网签样本交叉核实，客观事实归档至 `data/evidence/`。面向用户输出时，保持沉稳专业，直接呈现客观事实与核查结论，无需外显展示"营销甄别对照表"。

1. **基本盘事实表格**：小区/项目名、城市/区/板块、地址、类型、面积、户型、楼层/总层、梯户比、朝向、建成年代、容积率、总户数、物业与物业费、总价（万元）、单价（元/㎡）、挂牌渠道、房源核验码。
2. **关键客观核验要点（Key Verified Facts）**：
   直接列出经过交叉验证的核心客观事实（规自局控规性质、真实步行距离、学位锁定状态、真实成交折价弹性等），作为本报告评分的基石。

## Block B — 需求匹配 Fit

**两遍规则**（防锚定）：

- Pass 1：只读需求画像（`config/profile.yml` + `_profile.md`），列出各项需求并标注重要性 enum：`critical / high / meaningful / preferred / low_signal`。重要性的依据只能是画像明示内容（"必须电梯"→ critical）、`_profile.md` 硬规则、或 **家庭结构衍生需求**（intake 生成的"家庭结构 → 衍生需求"映射），不得来自"市场常识"猜测。
- Pass 2：逐项对照房源事实填匹配度：`✅ 满足 / ➖ 接近 / ⚠️ 牺牲项 / ⛔ 不满足`。

需求项至少覆盖：预算（区间+walk-away）、户型/面积、通勤（含第二通勤者）、学区（按入学基准年）、**电梯与楼层对老人/幼儿的适配**、医疗距离等级、商业配套等级、特殊需求逐项、排除清单。

输出映射表（≤ 14 行）+ 硬性 DQ 检查结果（逐条对照 `_profile.md`，命中即按 `_shared.md` 封顶并在报告首行标注）。末行注明：Fit 的失分只影响 Global 的定性理由，映射行数不参与算术。

## Block C — 价格合理性与历史走势 Price

按顺序给出，每项带可靠度档位：

1. **本套基本盘**：总价、单价、挂牌时长、调价历史与调价幅度。
2. **历史成交与抗跌性走势**：
   - 该小区/对标板块近 1-3 年成交均价演变（相对于历史峰值回调幅度、近半年筑底走势）。
   - **挂牌-成交真实折价空间**：同类户型实际成交相较挂牌价的折价弹性（测算砍价安全区间，如 3-5% 或 5-8%+）。
   - **去化周期与换手率**：年均换手套数、平均在架成交天数，判断是否存在"流动性陷阱"。
3. **价格锚点与流动性信号**：按 `_shared.md` 锚点阶梯取最高可得档；结合近 30 天带看与在售去化信号判断供需平衡。
4. 结论：`低于市场 | 接近市场 | 高于市场` + `筑底企稳 | 阴跌回调 | 溢价偏高` + 议价弹性空间档（紧/正常/宽）。

## Block D — 地段配套与生活圈四大核心支柱 Location

> **评估核心权重**：在阶段二评估中，金额只要在预算区间内即不构成决定性差异。**真正决定自住幸福感与打分权重的，是四大日常生活配套的硬核事实**。严禁通用套话，每类必须给出具体名称、实测距离与真实数据：

1. **学区配套与中考升学硬核核查（极高打分权重）**：
   - **双学区对口**：对口小学与对口初中全称、办学历史、师资背景；
   - **升学机制与出口数据**：是否九年一贯制直升？初中近年中考“市重点（市实验性示范性高中）录取率/达线率”及四校八大录取样本；初中在区内的公办梯队排位与真实推进率；
   - **入学门槛与风险**：五年一户/六年一户执行情况、提前落户年限要求、跨区转学与插班空额。
2. **商业配套与推车生活圈**：
   - **下楼微动线**：下楼步行 5-10 分钟（400-800米）日常生鲜/菜场/早教生活圈，全职妈妈推车遛娃动线（人车分流、绿化步道）；
   - **区域核心商圈**：1.5-3km 大型商业综合体具体名称、车程或直达公交。
3. **医疗资源与儿科急诊**：
   - **儿童突发急诊**：车程 15-20 分钟内三甲医院/儿科专科医院名称与实际车程路线；
   - **社区医疗**：步行或近距社区卫生服务中心（负责儿童常规儿保、疫苗接种）。
4. **真实交通与出行**：
   - **公共交通**：拒绝中介“地铁盘”话术，给出真实高德实测步行距离与耗时；距地铁超 1.2km 必须如实标注需公交接驳，核验接驳公交线路及早晚高峰班次间隔；
   - **自驾通勤**：临近高架/高速出入口具体路口与距离，早晚高峰常态拥堵节点。
5. **城市空间规划与周边变量**：周边 1-2km 内已批未建地块法定控规用途（产业/绿地 vs 高密住宅抛压）；在建工程施工扬尘与噪音周期；远期高层规划采光遮挡风险。

## Block E — 房屋本体与居住体验 Property

1. **房龄三重影响**：①贷款年限与评估价影响 ②管道/电梯/外立面老化与维修基金余量 ③老城改造/拆迁预期 ④**建成年代多源核对**。
2. **电梯×楼层交叉判断**：有无电梯 × 楼层位置（一楼返潮/采光遮挡、**二层返水风险（独立排水是否改造）**、顶楼渗漏与夏热、设备层、腰线层）× 家庭结构（老人/婴儿车/搬家）。
3. **户型工程与得房率实测**：暗间、长走廊、异形空间、动静分区、真洋房 vs 高层实际得房率、开间与进深实测；反查挂牌话术暗改违建风险。
4. **物业与社区管理**：物业品牌与物业费、门禁安保、软素质代理信号。
5. **车位与出行**：车位比、车位租售价格、充电桩条件、人车分流。
6. **当地政策全口径税费精算（买方到手现金成本）**：
   - **政策来源与法定文号（必须明确引用）**：如《财政部 税务总局 住房城乡建设部关于促进房地产市场平稳健康发展有关税收政策的公告》（财政部公告2024年第16号）、当地市住建委与税务局最新细则。
   - **透明代入计算公式全过程（拒绝仅给总数）**：
     * **契税**：`计税总价 × 适用税率`（首套/二套、≤140㎡按 1.0%，>140㎡按 1.5% 或 2.0%）。例：`485万 × 1.0% = 4.85万元`。
     * **增值税及附加**：满2年免征；不满2年：`计税总价 ÷ (1 + 5%) × 5.3%`。
     * **个人所得税**：满五唯一免征；非满五唯一：`计税总价 × 1%`（核定征收）或差额 20%。
     * **交易杂费与中介费**：中介费率（按 1%~2% 测算）、登记费（80元）。
     * **全口径现金支出汇总**：首付款 + 税费合计 + 中介杂费。
7. **流通性**：同小区在售量与月均去化、将来转手难度的定性判断。

## Block F — 风险与政策约束信号 Risk

清单式逐项检查，输出 `未发现 | 注意 | 高风险 | 未核实`：
- **当地政策约束**：限购资格核验、公积金新政额度与缴存年限匹配度、商贷认房不认贷适用性、学区五年一户/六年一户锁定年份核验、限售转让约束。
- **产权与交易**：抵押、查封、共有权人、满五唯一与上次交易日期交叉核验、户口占用、官方核验码备案一致性。
- **主体与房屋**：开发商交付风险、事故房/凶宅核查、渗漏与承重墙改动、挂牌信号词反查。
- **社区构成（回迁混居核验协议，2026-09 实战校准）**：三处交叉——①链家小区库「交易权属」字段（已验证有判别力：含「动迁安置房」= 混居信号真实，非默认枚举，对照样本：示范湖滨家园=「商品房/使用权」无动迁项不命中）②本套详情页权属与房源介绍自述 ③物业费水平（动迁盘典型 0.9-1.5 元）与物业品牌。判读：小区库含「动迁安置房」→ 默认混居 DQ 封顶（对照样本：示范杰城D街坊=混合+自述+低物业费多源印证）；**政府公示交叉验证（可远程执行，政府背书）**：土地出让公告、环评公示、建设工程设计方案公示（规资局/区政府官网）会写明地块用途（动迁安置房/商品房）与**建设单位**——建设单位是判别"小区本体混居"还是"仅周边有安置房"的关键（实战案例：示范柏景湾=中骏置业开发，周边 E 地块安置房建设单位为示范置业 → 小区本体混居证伪，DQ 解除、保留环境减分；若建设单位为本地平台公司且无法证伪 → 维持封顶并写明解除条件）。豁免路径 = 用户修改 `_custom.md`。
- 结论三档：`低风险 | 注意 | 高风险`。高风险 → Global 封顶 2.5 并在报告首行标注原因。

## Block G — 同区域/同价位竞品横向对标与核心护城河（Competitive Benchmark）

> **拒绝脱离市场孤立评价**：必须选取同区域、相近总价（±30-50万）的 2-3 个代表性竞品小区进行横向对标，提炼三大核心洞察：

1. **核心护城河（Unique Moat / 相比竞品的压倒性优势）**：在该预算区间内，该房源为什么具有不可替代性？（如：同价位唯一的低密纯洋房四房、唯一九年制名校步行入校、唯一一级品牌物业）。
2. **硬性妥协与不可承受之痛（Critical Trade-offs / 相比竞品的致命劣势）**：选择它必须付出什么代价值得警惕？（如：距地铁站超 4km 无法步行、中考升学数据仍属新办序列缺乏十余年大考验证）。
3. **精准买家画像与决策分流（Who should buy this?）**：
   - **强烈推荐买**：具备什么生活特征的家庭？（如：自驾出行、极度追求居住空间尺度与洋房品质的改善家庭）；
   - **坚决劝退买**：什么特征的家庭买了一定后悔？（如：依赖地铁上下班的老人与双职工、对中考市重点率要求 100% 稳妥的家庭）。

## Score Breakdown 与多方案权衡推演（Scenario Trade-offs）

五维表格（每维：分数、**详细因果支撑依据（严禁空洞套话，必须说明因何加分、因何扣分）**、可靠度档位）+ **Global 综合研判**。

**绝不单向激进催促行动，必须输出对比方案矩阵**：
1. **得失清单（Pros vs Cons）**：如果选它，能锁定什么核心价值？必须承受什么妥协或潜在隐患？
2. **多情景推演（3 类方案对照）**：
   - **方案 A（积极推进方案）**：出价预期、税费到手总成本、关键核实与谈判切入点。
   - **方案 B（稳健观望/竞品替代方案）**：同板块或辐射圈内的替代对标选项，权衡换取更好户型/次新或学区代价。
   - **方案 C（画像微调重构方案）**：若该套房源卡在预算或通勤边界，提示如何通过微调画像假设释放新空间。

## Post-evaluation

1. 存报告：`reports/{NNN}-{小区slug}-{YYYY-MM-DD}.md`。编号优先用 `node scripts/reserve-report-num.mjs` 原子分配（3 位零填充）；脚本不可用时手动取 `reports/` 现有最大编号 +1。
2. 存客观事实档案：将交叉验证中查验的政务备案、不动产产调、法定控规图号、教育局施教区公示、历史网签成交明细归档至 `data/evidence/{NNN}-{小区slug}-evidence.md`，作为不可辩驳的客观事实支撑底稿。
3. 更新 `data/watchlist.md`：新房源新增一行；已存在的更新评分与风险列。
4. 回复用户：报告路径 + 客观事实档案路径 + 一段话结论 + 下一步建议。
