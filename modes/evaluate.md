# Mode: evaluate — 单房源六维评级

输入：房源 URL 或文字描述。输出：`reports/{NNN}-{小区slug}-{YYYY-MM-DD}.md` 评级报告 + watchlist 登记。前置阅读：`_shared.md`（评分体系）、`_profile.md`（存在时）、`_custom.md`（存在时）。

## Step 0 — 输入解析与信息补全

- URL：WebFetch 抓取挂牌页；失败时尝试一次搜索快照/其他平台同源挂牌，仍失败则请用户粘贴页面关键信息。
- 纯文字描述：直接采用，标"用户提供"。
- 信息缺口补全：联网搜索小区名+城市（限预算内，见 `_shared.md` 研究有界规则），优先补：所在区/板块、建成年代、物业费、同小区挂牌量。

**Gate — 信息充分性**：以下 5 项至少齐 4 项才进入评分：城市+区/板块、总价或单价、面积、户型、楼层/房龄任一。不足时列出缺口请用户补充或确认"按缺省评估"（缺失维度记 `— not evaluated`）。

## Step 1 — 房源类型检测

判定并写入报告：`二手住宅 | 新房(期房/现房) | 法拍房 | 商办公寓(40/50年) | 别墅 | 保障房/其他`；渠道：`链家 | 贝壳 | 安居客 | 中原 | 开发商直销 | 其他平台 | 用户转述`。类型影响后续侧重：

- 新房期房 → Risk 侧重的开发商资金链/交付风险、五证
- 法拍房 → Risk 侧重占用人/租约/欠费，默认建议用户引入法辅/律师
- 商办公寓 → 若画像硬性 DQ 排除商办，直接封顶并提示

## Block A — 房源概要

表格：小区/项目名、城市/区/板块、地址、类型、面积、户型、楼层/总层、朝向、建成年代、总价（万元）、单价（元/㎡）、挂牌渠道、挂牌时长（可得时）、TL;DR 一句话。

## Block B — 需求匹配 Fit

**两遍规则**（防锚定）：

- Pass 1：只读需求画像，列出各项需求并标注重要性 enum：`critical / high / meaningful / preferred / low_signal`。重要性的依据只能是画像明示内容（"必须电梯"→ critical）或 `_profile.md` 硬规则，不得来自"市场常识"猜测。
- Pass 2：逐项对照房源事实填匹配度：`✅ 满足 / ➖ 接近 / ⚠️ 牺牲项 / ⛔ 不满足`。

输出映射表（≤ 12 行）+ 硬性 DQ 检查结果（逐条对照 `_profile.md`，命中即按 `_shared.md` 封顶并在报告首行标注）。末行注明：Fit 的失分只影响 Global 的定性理由，映射行数不参与算术。

## Block C — 价格合理性 Price

按顺序给出，每项带可靠度档位：

1. 本套：总价、单价、挂牌时长、调价历史（有几次、方向）。
2. 同小区：近期成交价（成交数据 > 挂牌数据）、当前在售均价与在售量。
3. 同板块：2-3 个可比小区/项目的单价区间。
4. 结论：`低于市场 | 接近市场 | 高于市场` + 估计议价空间档（紧/正常/宽，仅挂牌数据以上支撑时给）。

数据只有"未核实"档时，Price 记 `— not evaluated` 并进待核实清单。

## Block D — 地段与配套 Location

表格逐项：交通（现状线路/距离，规划线路须标注"规划，未开通"）、学区（对口学校：**只陈述可核实的政策事实**，宣传语不采信）、医疗、商业、公园/环境。附嫌恶设施检查清单：高压线/变电站、垃圾站/污水处理、殡葬设施、厂房/化工、高架/铁路噪音、墓地——逐项标注 `未发现 | 存在 | 未核实`。

## Block E — 房屋本体与税费 Property

1. 本体：房龄、楼层（含顶层/底层/设备层提示）、朝向、户型结构（暗间/长走廊/异形）、装修状况、物业与物业费、梯户比。
2. 税费估算（中国二手房）：读 `templates/policy-notes.cn.yml` 的契税/增值税/个税行 → **联网核实 as_of** → 按持有年限/套数估算买方税费区间（万元），标注假设（如"满五唯一待核实"）。
3. 流通性：同小区在售量与月均去化、户型在当地的受众（刚需/改善），给出"将来转手难度"定性判断。

## Block F — 风险信号 Risk

清单式逐项检查，输出 `未发现 | 注意 | 高风险 | 未核实`：

- 产权：抵押、查封、共有人未确认、小产权/商办混合
- 交易：限购资格匹配（对照画像）、满五唯一与否、户口占用、学位占用（可得时）
- 主体：开发商资金链（新房）、中介资质（用户转述渠道时提示核实）
- 房屋：事故房/凶宅（搜索"小区名+凶宅/事故"）、渗漏/结构（挂牌信息通常不含，列入看房核查）
- 政策：学区政策变动风险（多校划片等）、规划兑现风险

结论三档：`低风险 | 注意 | 高风险`。高风险 → Global 封顶 2.5 并在报告首行标注原因。

## Score Breakdown 与结论

五维表格（每维：分数、一句话依据、可靠度档位）+ **Global 整体判断**（说明哪几维主导了结论、是否触发封顶）。分档结论照 `_shared.md`，并给出下一步：

- ≥ 4.0：提示可运行 `/house-ops deep-dive` 与 `/house-ops negotiate`
- < 3.5：明确建议放弃及理由
- 中间档：列出"补齐哪几个信息可以提高判断置信度"

## Post-evaluation

1. 存报告：`reports/{NNN}-{小区slug}-{YYYY-MM-DD}.md`（编号 = 现有最大 +1，3 位零填充）。
2. 更新 `data/watchlist.md`：新房源新增一行（状态 `已评估`）；已存在的更新评分列，状态保持不变。
3. 回复用户：报告路径 + 一段话结论 + 下一步建议。
