# Mode: negotiate — 沟通谈判建议

触发：`/house-ops negotiate [编号|小区名|URL]`。**前置条件：Global ≥ 4.0**（同 deep-dive 门槛规则）。

前置阅读：`_shared.md`、`_profile.md`（沟通偏好）、该房源的评估/deep-dive 报告。

## 红线（每次输出前自检）

AI 只**起草**话术与清单，绝不发送、不承诺、不代表用户联系任何人；不涉及任何款项操作。所有模板中不替用户编造事实（如假装"看了很久别的盘"），需用户确认属实的留占位符。

## Step 0 — 输入与素材

定位房源与报告（无报告则先评估）。提取谈判素材：挂牌时长、调价历史、在售竞品量、价格可靠度、风险项、deep-dive 的待核实清单（若有）。

## Block A — 向房东核实的问题清单

按优先级排列，每条附"为什么要问"。默认清单（按房源类型裁剪）：

1. 出售原因与急迫度（置换/变现/继承——影响议价空间）
2. 产权：是否唯一住房？持有满几年？有无共有人，共有人是否知情同意出售？
3. 抵押/查封状态；若有抵押，解押方案与周期
4. 户口是否占用，何时迁出（写入合同）
5. 学位是否被占用（若画像学区权重 ≥ 中）
6. 现有租约（买卖不破租赁）与交房时间
7. 家具家电哪些留、物业费水电是否结清

## Block B — 向中介核实的问题清单

1. 佣金率与支付节点；是否独家委托
2. 房东心理价位与出售时间线（中介口述，标可靠度）
3. 该小区近期真实成交（请求出示成交记录）
4. 带看安排：房东是否自住、看房时间限制
5. 交易流程节点预估（从下定到过户）

## Block C — 议价分析

基于报告素材输出：

- **议价空间档**：`紧（0-3%）| 正常（3-8%）| 宽（8%+）`，依据：挂牌时长、调价方向、竞品数量、报价 vs 成交价差、房东急迫度信号。只有挂牌数据以上可靠度时才给档位，否则写"信息不足"。
- **杠杆清单**：本套的减分项（楼层/装修/房龄/在售竞品更多/挂牌久）——谈判时可用的事实，不是贬低话术。
- **底线对照**：画像 walk-away 价与本套当前挂牌的关系，明确"可谈到什么价位才值得买"。

## Block D — 分轮报价策略

| 轮次 | 动作 | 要点 |
|---|---|---|
| 首轮 | 首次约看+试探 | 只问不报价；用 Block A 问题试探急迫度 |
| 二轮 | 首次出价 | 依据议价空间档给区间；附出价理由（竞品成交价，非情绪） |
| 三轮 | 台阶加价 | 每步 ≤ 上步差额一半；换小权益（家具家电/税费承担/交房时间）代替加价 |
| 收口 | 达到心理价位 | 当场确认交易条件清单，约定时间签正式文件 |

附：心理底线提醒（walk-away 不因现场氛围上移）；首轮出价的具体数字区间（基于 Block C 计算，用户可调）。

## Block E — 带看现场核查清单

打印式清单，逐项可勾选：

- 渗水霉斑：外墙/窗边/卫生间顶/阳台
- 噪音：关窗/开窗各站 1 分钟；早晚各一次更好
- 采光：看房时段的日照；问清冬季情况
- 水压电压、下水；燃气类型
- 楼道与邻居：楼道堆物、邻里构成、物业响应
- 周边实测：到地铁/学校/菜场的步行真实时间
- 对照评估报告的"待核实清单"逐项闭环

## Block F — 沟通话术草稿

按画像沟通偏好（默认中文、微信文字风格）输出三段草稿，各 ≤ 150 字：

1. 首次联系中介（表明需求画像匹配点、约看意向、不暴露预算上限）
2. 约看确认（时间、到场人、需要房东配合的事项）
3. 首次出价（出价数字 + 竞品/成交依据 + 条件）

每段草稿后附一行"发出前请确认"的占位符说明（时间/价格/姓名）。

## 输出与收尾

谈判建议以报告附录形式写入 `reports/{同编号}-...-negotiate.md`（或用户要求仅在对话输出时直接展示）。Post：若用户已约看，更新 watchlist 备注追加「已约看；日期」；提醒用户把带看中核实到的新信息带回，用于修订评分。
