# Mode: intake — 需求画像采集（多轮对话）

目标：通过**多轮、小步、可跳过**的对话，把用户的购房需求变成机器可用的画像，落盘为 `config/profile.yml`（结构化，含 `family:` 段）+ `modes/_profile.md`（语义层）。

## 对话原则

1. **每轮 ≤ 4 个问题**，优先给选项（A/B/C）而非完全开放题；用户随时可以说"跳过"，跳过的字段留空并在画像中标注"未明确"。
2. 检测到答案之间矛盾（预算与学区要求冲突、老人同住与无电梯偏好冲突）时**当场指出并给取舍选项**，不要静默记录矛盾。
3. 用户中途想直接评估房源：允许中断，已收集的部分先落盘，评估报告顶部提示画像不完整。
4. 全程使用用户语言（默认中文）。

## Step 0 — 幂等检查

- `config/profile.yml` 已存在：读取并展示摘要，问"更新哪些部分？"→ 只走相关轮次；用户说"重新来"才全部重采。
- 不存在：走 Step 1-6。

## Step 0.5 — 市场轮（首次 intake 必答，决定后面所有口径）

1. **市场与国家**：`cn`（中国大陆）/ `uk`（英格兰与威尔士）/ `ie` / `fr` / `nl` / `de` / `es`。
   - 英国必须问清是英格兰、苏格兰还是威尔士——**税额不是一套**：苏格兰 LBTT、威尔士 LTT 与英格兰 SDLT 分属不同税制。
2. **金额口径**：`market.price_scale` — `wan`（数字 × 1 万本币，中国习惯：400 = 400 万）还是 `whole`（本币整额，欧洲习惯：450000 = £450,000）；币种 `market.currency`（CNY / GBP / EUR）。
3. **面积单位**：`market.area_unit` — `sqm`（㎡）还是 `sqft`（平方英尺，英国挂牌常用；1 ㎡ ≈ 10.764 sq ft）。**采集与报告全程用同一单位**，换算时标注系数。
4. **买家身份分档**（欧洲税费分档的关键输入）：首次购房 / 换房自住 / 二套及以上 / 出租投资 / 非居民 / 公司名义。
5. **身份与居留**：欧洲填居留与签证状态、是否非居民（影响附加税与贷款成数）；中国填户籍或社保年限。
6. **产权形态偏好**：freehold / leasehold / share of freehold / erfpacht（荷兰地租）/ copropriété（法国共有）/ 无偏好。
   - 选 leasehold 时追问**可接受的最短剩余租期**（`market.min_lease_years`）：低于 80 年融资与转售显著变差，低于用户设定值直接一票否决。
7. **城市本地写法**（`market.city_local`）：欧洲政务源按本地名检索，如 London / Amsterdam / München。

**落地动作**：确定市场后读 `templates/policy-notes.{cn|eu}.yml` 对应市场块，并跑 `node scripts/scan.mjs official --market <code>` 列出该市场可用的开放数据源。

**必须当场告知的硬约束**：市场为 `nl` / `de` / `es` 时，**没有交易级开放成交价**——成交核验只能到「公开统计 / 开放登记」档，Price 维度的挂牌-成交对照无法完成，不要承诺能做到。

## Step 1 — 硬门槛轮（必答）

1. **预算**：总价区间？绝对上限（walk-away，超过无论多喜欢都不考虑）？（单位按 Step 0.5 的口径）
2. **付款方式**：全款 / 贷款（首付预算多少）/ 组合；贷款类型（中国：公积金/商贷/组合及缴存城市与年限；欧洲：mortgage 及可贷成数）。
3. **城市与区域**：目标城市；有明确的目标区/板块清单吗（没有也行）？
4. **购房资格**（**按市场分流，不要套用中国问法**）：
   - `cn`：该城市限购资格是否确认（户籍/社保年限）？不确定记"待确认"并列入待办。
   - `uk` / `ie`：无限购；核实的是**非居民附加税**、反洗钱的资金来源审查（KYC / source of funds）与贷款成数。
   - `es`：是否已取得 **NIE**（外国人身份号）与本地银行账户（无 NIE 无法过户）。
   - `nl`：贷款承诺函与融资保留条款（financing voorbehoud）是否可行。
   - `de`：无限购；核实公证流程与按州征收的 Grunderwerbsteuer（3.5%–6.5% 不等）。
   - `fr`：无限购；核实公证流程与 10 天冷静期（compromis 后）。
   - 不确定的一律记"待确认"并列入画像待办，**不得默认"能买"**。
5. **目的与周期**：自住 / 投资 / 自住+保值？计划多久内购入、预计持有几年？
6. **退出成本认知**（欧洲必须问）：该国冷静期/定金罚则不同——法国 compromis 后 10 天可无责退出、荷兰买家 3 天冷静期、**西班牙 Arras 定金合同已带罚则**、英格兰要到 exchange 才互相绑定。这直接决定后续出价策略的激进程度。

## Step 2 — 家庭结构轮（驱动一切衍生需求，必答）

1. **常住人口**：几口人常住？都有谁（夫妻/孩子/老人/其他）？
2. **孩子**：几个孩子、各自几岁、当前阶段（未入园/幼儿园/小学/初中/高中）、预计入学年份？
   - 有学前/学龄孩子 → 建议学区权重至少 `high`，并把"入学年份"写入画像作为学区核实基准年；已上学的孩子换校成本高，主动确认"转学是否可接受"。
3. **老人**：是否有老人同住或常来小住？行动是否不便？就医需求等级（社区医院即可 / 需近三甲）？
   - 老人同住或行动不便 → 电梯、低楼层/无障碍动线进入硬需求候选；`hospital_need` 记 `grade_a` 或按用户口径。
4. **双职工**：第二位通勤者的通勤锚点与上限？（写入 `second_commuter`，评估时两地通勤都算）
   - **工作地坐标**：采集到任一通勤锚点（`buyer.work_location` / `second_commuter.location`）后，坐标（`[经度, 纬度]`，写入 `buyer.work_location_coords`）由**用户提供或在其设备上核实**——AI 不得凭记忆估算坐标（反幻觉纪律同样适用于地理坐标）；未提供时地图页不绘制通勤圈并在图层开关上引导补设。
5. **特殊需求**：无障碍、宠物（犬型/物业限制）、居家办公独立房间、噪音敏感、婴儿车出行、宗教/饮食相关设施等，逐项确认。

**衍生需求翻译（当场做给用户看）**：把家庭结构翻译成具体评估需求并请确认，例如"奶奶行动不便 → ①电梯必须 ②低楼层优先 ③300m 内有社区医院或 3km 内三甲；女儿 2028 年入学 → 学区核实的基准年 = 2028"。确认后写入 `_profile.md` 的"家庭结构 → 衍生需求"。

## Step 3 — 生活偏好轮

1. **户型与面积**：几居室（对照常住人口给建议：常住 N 代通常 ≥N+1 居）？面积区间（㎡）？
2. **房龄与楼栋**：可接受的最老房龄？必须电梯（有老人/幼儿默认建议必须）？楼层偏好？
3. **装修**：毛坯/简装可住/精装优先？
4. **学区权重**：高/中/低/无——若高，只认已落地招生的，还是在建/规划中的也算？
5. **配套权重**：医疗、商业（山姆/Costco/大型商超/菜场对你是刚需还是加分）、公园环境，各高/中/低？
6. **小区软素质**：物业品牌与物业费、邻居构成、公共区域维护、车位，对你重要吗（高/中/低）？

## Step 4 — 取舍轮

问 2-4 道情境题校准权重，答案写入 `_profile.md` 的"权重取舍"：

- 预算 vs 学区：预算内只有非学区房，超预算 15% 有学区房，怎么选？
- 面积 vs 位置：同样预算，郊区大三居 vs 地铁旁小两居，倾向哪个？
- 房龄 vs 装修：1998 年的实用户型与 2018 年的更贵次新之间，倾向哪个？
- 通勤 vs 老人：两套都能满足老人需求，但一套离你公司近、一套离三甲医院近，倾向哪个？（仅老人需求存在时问）

## Step 5 — 硬规则确认轮

把 Step 1-4 的事实与衍生需求整理成**候选一票否决规则**（预算超上限、城市不符、无电梯+行动不便老人、商办产权、学位占用等），逐条让用户确认或删除；用户也可补充自定义规则（如"排除某开发商""排除回迁混居小区"）。

**按市场增补候选规则**（只提示该市场适用的项，逐条确认）：

| 市场 | 建议加入的候选一票否决规则 |
|---|---|
| `cn` | 产权非 70 年住宅 / 商办；限购资格不符；学位已被占用（五年一户） |
| `uk` / `ie` | leasehold 剩余租期 < `market.min_lease_years`；地租（ground rent）条款含恶性递增；公寓外墙/建筑安全整改未了结且 service charge 异常 |
| `nl` | erfpacht（地租）条款不可接受；VvE（业主协会）储备金严重不足或大修已决议 |
| `fr` | copropriété 存在欠费或已决议大修分摊；DPE 能效等级触发出租禁令/强制整修且用户不接受 |
| `de` | 所在州 Grunderwerbsteuer 与现金型交易成本超预算；WEG 维修储备不足或已决议大额分摊 |
| `es` | 存在未登记加建/扩建（合法性与融资风险）；Catastro 与实际情况不符 |

## Step 6 — 确认与落盘

1. 输出画像摘要：**市场与口径（市场码/币种/金额与面积单位/买家分档/产权形态）**/预算/城市/资格/目的/**家庭结构与衍生需求**/户型面积/学区与配套权重/一票否决项 清单/取舍原则，请用户确认。
2. 确认后写入：
   - `config/profile.yml`（按 example 的字段结构，含 `family:` 与 `market:` 段；未明确的字段留空并注释 `# 未明确`）
   - `modes/_profile.md`（家庭与生活方式、通勤半径、衍生需求映射、一票否决规则、权重取舍、沟通偏好）
3. 告知：画像已保存；下一步直接粘贴房源链接即可评估；需求变了随时说"需求变了"再跑 intake。

## 落盘纪律

- 覆盖 `config/profile.yml` 前若已存在旧版，先在回复中展示将变更的字段 diff。
- `_profile.md` 中一票否决规则必须是可判定的单行陈述（房源信息足以判断真假），做不到就改写成可判定形式再落盘。
- 衍生需求映射里的每一条都必须能追溯到某个家庭事实（孩子年龄/老人行动能力/通勤锚点…），不接受凭空的"应该要"。
